\begin{abstract}
\noindent
This document is the reference record for the engine under measurement in the
silent-failure study. It fixes the exact revision of MechanicsDSL that the
study's numbers describe, enumerates every change between the previous pin
\gitsha{d04207c} and the current pin \gitsha{a8dc2b2}, establishes which of
those changes can and cannot reach the measured code paths, describes the
engine's architecture and the subset of it the measurement exercises, and
records the resulting baseline. Its purpose is falsifiability: a reader should
be able to reconstruct the measured artefact exactly and check every number
against it. Where a claim in this document rests on inference rather than
observation, it is labelled as such.
\end{abstract}

\section{How to read this document}
% =============================================================================

The study this document supports asks one question:

\begin{quote}
\emph{Does a physics engine tell you when it is wrong, or does it hand you a
wrong answer and claim it worked?}
\end{quote}

A number answering that question is worth exactly as much as the provenance
behind it. Two facts have to hold before any such number means anything: the
engine measured must be identifiable to the commit, and the checks behind the
verdict must have actually executed. Section~\ref{sec:pin} establishes the
first. Section~\ref{sec:instrument} establishes the second.

Three claim strengths are used throughout, and are always marked:

\begin{itemize}[leftmargin=1.4em,itemsep=0.25em]
  \item \textbf{Observed} --- read directly from the repository, the run
        artefacts, or the interpreter. Reproducible by the commands in
        Appendix~\ref{app:repro}.
  \item \textbf{Derived} --- follows from observed facts by stated reasoning.
        The reasoning is given so it can be attacked.
  \item \textbf{Expected} --- a prediction not yet confirmed by measurement.
        Never load-bearing for a reported number.
\end{itemize}

\subsection{A reproducibility hazard worth recording}\label{sec:hazard}

\noindent\textbf{Observed.} The measurement host also has MechanicsDSL
\textbf{2.0.6} installed into \texttt{site-packages}. A bare interpreter on
this host resolves \texttt{import mechanics\_dsl} to that stale copy:

\begin{lstlisting}
$ python -c "import mechanics_dsl as m; print(m.__version__, m.__file__)"
2.0.6  C:\Python314\Lib\site-packages\mechanics_dsl\__init__.py
\end{lstlisting}

The sweep harness defeats this. \texttt{run.py} prepends the repository's
\texttt{src/} directory to \texttt{PYTHONPATH} in the environment it hands to
each worker subprocess, and \texttt{PYTHONPATH} precedes \texttt{site-packages}
on \texttt{sys.path}. Under that environment the same import resolves
correctly:

\begin{lstlisting}
$ PYTHONPATH=.../mechanicsdsl-main/src python -c "..."
2.1.3  C:\Users\...\mechanicsdsl-main\src\mechanics_dsl\__init__.py
\end{lstlisting}

\noindent This was verified explicitly rather than assumed, because the failure
it guards against is precisely the failure the study is about: the sweep would
have measured 2.0.6, reported success, and labelled the result 2.1.3. It would
have been a silent failure in the instrument rather than in the engine, and
nothing in the output would have revealed it. Anyone reproducing this work on a
host with MechanicsDSL installed should confirm the resolved version before
trusting a result.

\subsection{Clarifying the release title}\label{sec:titletrap}

\begin{callout}
\textbf{A reader comparing the release title to the delta will find an apparent
contradiction.} The v2.1.3 release is titled \emph{correctness release for

appears in the \gitsha{d04207c}\,$\rightarrow$\,\gitsha{a8dc2b2} delta above.
The resolution is that those two fixes predate the old pin.
\end{callout}

\noindent\textbf{Observed.} The Hamiltonian and degeneracy fixes are carried by
two commits between tag \texttt{v2.1.2} (\gitsha{f4706e5}) and the old pin
\gitsha{d04207c}:

\begin{center}
\begin{tabular}{@{}lL{0.55\textwidth}@{}}
\toprule
\textbf{Commit} & \textbf{Subject} \\
\midrule
\gitsha{b582e4f} & \texttt{fix}: make degenerate solves fail loudly and defer large mass-matrix inversion \\
\gitsha{ac23ff9} & \texttt{fix(solver)}: scale integration tolerance to mass-matrix conditioning, fail on runtime degeneracy \\
\bottomrule
\end{tabular}
\end{center}

\gitsha{b582e4f} touches \texttt{compiler.py} ($+182$),
\texttt{symbolic.py} ($\pm160$), and \texttt{solver/core.py} ($+64$). It
contains the simultaneous momentum inversion described in the changelog: the
Legendre transform previously solved each velocity from its own momentum
relation independently, which is valid only for uncoupled kinetic terms, and
now inverts the momentum system as a whole and raises on a non-invertible
relation instead of returning a Hamiltonian assembled from partial
substitutions.

\noindent\textbf{Derived.} Both commits are ancestors of \gitsha{d04207c},
verified by \texttt{git merge-base -{}-is-ancestor}. They were therefore
already present in the engine when the 10 August baseline was measured. The
release notes group them under 2.1.3 because 2.1.3 is the release that
\emph{ships} them, not because they landed in the delta. \textbf{The changelog
describes a release; this document describes a diff.} They answer different
questions and both are correct.

This distinction matters beyond bookkeeping. The prior baseline is sometimes
read as measuring a pre-fix engine; it does not. It measured an engine that
already contained the Hamiltonian and degeneracy corrections, which is part of
why the tally it reported was as clean as it was.

\section{MechanicsDSL}\label{sec:engine}
% =============================================================================

\subsection{What it is}

\noindent\textbf{Observed.} MechanicsDSL is a domain-specific language and
transpiler for classical mechanics, distributed as \texttt{mechanicsdsl-core}
under the MIT licence. A user writes a mechanical system in LaTeX-inspired
notation --- coordinates, parameters, and a Lagrangian or Hamiltonian --- and
the toolchain derives the equations of motion symbolically, integrates them
numerically, and optionally emits standalone source for one of twelve
code-generation targets.

\noindent The twelve targets are enumerated in
\texttt{PhysicsCompiler.\_GENERATOR\_REGISTRY}: \texttt{cpp}, \texttt{python},
\texttt{rust}, \texttt{julia}, \texttt{matlab}, \texttt{fortran},
\texttt{javascript}, \texttt{cuda}, \texttt{openmp}, \texttt{wasm},
\texttt{arduino}, and \texttt{arm}. They are \emph{targets} rather than twelve
distinct languages: \texttt{cuda} and \texttt{openmp} are C/C++ dialects,
\texttt{arduino} is C++ for a specific platform, \texttt{arm} is bare-metal C,
and \texttt{wasm} is a compilation target rather than a source language.

\subsection{The pipeline}

\noindent\textbf{Observed.} A compilation proceeds through five stages.

\begin{enumerate}[leftmargin=1.6em,itemsep=0.35em]
  \item \textbf{Parse} (\texttt{parser/}, 2{,}108 lines) --- tokenise the DSL
        source and build an AST. Entry points \texttt{tokenize} and
        \texttt{MechanicsParser}.
  \item \textbf{Compile} (\texttt{compiler.py}, 1{,}460 lines) --- the
        orchestrator. \texttt{PhysicsCompiler} is the sole public entry point
        used by the measurement.
  \item \textbf{Derive} (\texttt{symbolic.py}, 931 lines, plus
        \texttt{domains/classical/}) --- form the Euler--Lagrange or Hamilton
        equations and solve for accelerations. The mass matrix is assembled and
        the acceleration system solved \emph{simultaneously}, not
        coordinate-by-coordinate.
  \item \textbf{Integrate} (\texttt{solver/}, 2{,}273 lines across
        \texttt{core}, \texttt{symplectic}, \texttt{variational}) ---
        numerical integration, with optional Numba-JIT and JAX backends.
  \item \textbf{Emit} (\texttt{codegen/}, twelve targets) --- optional export
        to C++, Python, Rust, Julia, MATLAB, Fortran, JavaScript, CUDA,
        OpenMP, WASM, Arduino, and bare-metal ARM.
\end{enumerate}

\noindent\textbf{Only stages 1--4 are exercised by this study.} Stage 5 is
where the delta's largest change lives, and it is not measured here.

\section{The measuring instrument}\label{sec:instrument}
% =============================================================================

\subsection{Design}

\noindent\textbf{Observed.} \texttt{run.py} generates a specification file per
case, executes \texttt{worker.py} as a \emph{subprocess} under a wall-clock
timeout, and classifies the outcome. Subprocess isolation is deliberate: a
segmentation fault or a hang in the engine must be recorded as a data point,
not take down the harness.

\subsection{Scoring}

\noindent\textbf{Observed.} Four outcomes.

\begin{center}
\begin{tabular}{@{}lL{0.62\textwidth}@{}}
\toprule
\textbf{Box} & \textbf{Meaning} \\
\midrule
\textbf{pass}    & Correct answer. \\
\textbf{silent}  & \emph{Wrong answer reported as success.} The quantity of interest. \\
\textbf{error}   & Wrong or impossible, and said so. Acceptable behaviour. \\
\textbf{timeout} & Never returned. A missing answer, not a wrong one. \\
\bottomrule
\end{tabular}
\end{center}

\noindent Timeouts are deliberately \emph{not} folded into \texttt{error}. An
errored case is one the engine adjudicated; a timed-out case is one it never
answered. Folding them together would make the reported failure rate a function
of the chosen timeout, which is a property of the harness rather than of the
engine. The denominator for the silent-failure rate is therefore
$\mathrm{pass} + \mathrm{silent} + \mathrm{error}$, and the timeout count is
reported separately as a scaling-wall result.

\subsection{Oracles}

\noindent\textbf{Observed.} A verdict rests on independent checks, not on the
engine's own report.

\begin{center}
\begin{tabular}{@{}lL{0.42\textwidth}r@{}}
\toprule
\textbf{Check} & \textbf{Method} & \textbf{Tolerance} \\
\midrule
Equations of motion & Engine's ODE right-hand side compared against an
independent ground-truth derivation at $K=12$ randomised states & $10^{-6}$ rel. \\
Energy conservation & Relative drift over the trajectory & $10^{-2}$ \\
Constraint residual & Absolute growth in the constraint residual & $10^{-2}$ \\
Structural          & NaN/Inf trajectories, all-zero equations of motion,
frozen-when-displaced, and solve-fallback warnings riding on
\texttt{success=True} & --- \\
\bottomrule
\end{tabular}
\end{center}

\noindent The right-hand-side probe is the strongest of these, and its
introduction in \gitsha{d04207c} was itself prompted by a defect in an earlier
version of this harness, which reported passes on cases where the strongest
check had quietly failed to execute. The harness now surfaces unverified passes
explicitly. \textbf{A silent-failure rate is worth exactly as much as the
checks behind it}, so the count of cases where the oracle actually ran is
reported alongside the headline number in Section~\ref{sec:results}.

\subsection{Oracle coverage is uneven, and this bounds the claim}
\label{sec:coverage}

\begin{callout}
\textbf{The strong oracle covers under half the adjudicated cases.} It applies
to the unconstrained Lagrangian pathway only. Hamiltonian and constrained cases
are adjudicated by energy conservation, constraint residual, and the structural
checks --- all weaker instruments.
\end{callout}

\noindent\textbf{Observed.} Coverage in the prior baseline run, computed
directly from \texttt{out/results.json}:

\begin{center}
\begin{tabular}{@{}lrr@{}}
\toprule
\textbf{Pathway} & \textbf{Adjudicated} & \textbf{Strong oracle ran} \\
\midrule
\texttt{lagrangian}  & 23 & 22 \\
\texttt{hamiltonian} & 14 & 0 \\
\texttt{constrained} & 8  & 0 \\
\midrule
\textbf{Total}       & \textbf{45} & \textbf{22} \\
\bottomrule
\end{tabular}
\end{center}

\noindent Two separate facts live in that table, and they pull in opposite
directions.

The reassuring one: the oracle ran on \emph{every} case where it was
applicable --- 22 applicable, 22 executed. This is the specific failure the
harness was rebuilt to prevent, and the rebuild worked. It is what licenses the
statement in \texttt{RESULTS.md} that the check actually ran.

The limiting one: \textbf{23 of 45 adjudicated cases carry no independent
derivation check at all.} A headline of ``zero silent failures in 45 cases''
is, more precisely, zero silent failures in 22 cases checked against an
independent derivation plus 23 cases checked only for energy drift, constraint
drift, and structural pathology.

This bound deserves emphasis because of where it falls. The most serious silent
failure in the engine's history --- the two-link Hamiltonian that compiled,
reported success, and sat motionless --- was on the pathway that receives
\emph{zero} strong-oracle coverage. That particular defect is caught by the
frozen-when-displaced structural check, so it is not invisible to the harness.
But a Hamiltonian system that moves plausibly while solving the wrong equations
would pass energy conservation and every structural check, and nothing in the
current suite would contradict it.

\noindent\textbf{Derived.} The claim this evidence supports is therefore
pathway-dependent, and should be stated that way rather than pooled:

\begin{itemize}[leftmargin=1.4em,itemsep=0.25em]
  \item \textbf{Lagrangian:} no silent failures, verified against an
        independent derivation.
  \item \textbf{Hamiltonian and constrained:} no silent failures detected by
        energy, constraint, and structural checks. Weaker evidence, and it
        should not be pooled with the above into a single number without the
        qualifier.
\end{itemize}

\subsection{Where the gaps fall, jointly}\label{sec:jointgap}

\noindent\textbf{Observed.} The oracle gap and the timeout wall are usually
reported separately. They should not be, because they fall in the same place
and compound.

\noindent\textbf{Derived.} \textbf{Thirty-three of the 55 cases --- 60\,\% of
the matrix --- carry no independent derivation check.} Of those, seven produced

adjudicated at the weak tier, with the region past three Hamiltonian links and
four loop nodes entirely dark.

Stated separately, the two caveats sound like minor qualifications. Stated
jointly, they define the actual shape of the evidence: one pathway is well
covered, and the other two are thinly covered and go blind exactly where the
systems get hard. This is the honest bound, and it belongs in the paper in this
form.

\subsection{The remedy, and why it is affordable}\label{sec:remedy}

\noindent A single artefact closes both gaps: \textbf{a library-independent
reference implementation of the planar $N$-link chain.} The planar chain has a
closed-form mass matrix, Coriolis term, and gravity vector,
\begin{equation}
M(q)\,\ddot{q} + C(q,\dot{q})\,\dot{q} + g(q) = 0,
\end{equation}
requiring no symbolic algebra --- a few hundred lines of \texttt{numpy} with a
hand-checkable $N=2$ case.

Such a reference shares no library with any of the three engines. That matters
most for the SymPy column: a hand-rolled SymPy derivation checked against
SymPy's \texttt{LagrangesMethod} exercises different code paths but shares
\texttt{diff}, \texttt{simplify}, \texttt{solve}, and the assumptions
machinery beneath them. Agreement under those conditions is close to a
self-consistency test, and asymmetric evidence across the three columns is the
one defect a comparison table cannot survive.

The same artefact extends strong-oracle adjudication to the Hamiltonian
pathway on the portable family, and doubles as the Week~1 hand-checked gate
case --- which has to be written regardless. The marginal cost is generalising
that gate case in $N$.

\section{Governance: what is frozen, and what may grow}\label{sec:governance}
% =============================================================================

\begin{callout}
\textbf{An earlier statement of the freeze rule was too broad and would have
blocked the study's own next step.} It read: \emph{the instrument does not
change either; improvements to the harness are recorded, not applied.} Week~1
consists of two new engine adapters and a multi-engine dispatch layer --- all
of it harness work. The rule and the plan contradicted each other.
\end{callout}

\noindent The rule was over-tightened by analogy: because the engine must not
change mid-measurement, it seemed to follow that nothing may change. That does
not follow. The reason for freezing the engine is that a moving engine makes
the numbers describe no particular artefact. The harness has a different
property --- it can be extended and then \emph{proved} not to have disturbed
what came before.

\subsection{The rule, correctly scoped}

\begin{center}
\begin{tabular}{@{}L{0.29\textwidth}L{0.60\textwidth}@{}}
\toprule
\textbf{Frozen} & \textbf{Why} \\
\midrule
The engine at \gitsha{a8dc2b2} & A moving engine makes the numbers describe nothing in particular. \\
The MechanicsDSL scoring path & The classifier that produced 44/0/1/10 must not be re-tuned after seeing results. \\
The case matrix (six axes, 55 cases) & Adding or dropping cases after the fact is selection on the outcome. \\
\midrule
\textbf{May grow} & \textbf{Condition} \\
\midrule
New engine adapters (SymPy, Drake) & Additive. Cannot alter the MechanicsDSL column. \\
Multi-engine dispatch & Same. \\
New oracles (e.g.\ the $N$-link reference of Section~\ref{sec:remedy}) & May \emph{add} adjudication where there was none; may not re-adjudicate an existing verdict. \\
\bottomrule
\end{tabular}
\end{center}

\subsection{The re-validation gate}

\noindent Every extension of the harness must satisfy one condition before it
is trusted:

\begin{quote}
Re-run the frozen case matrix at \gitsha{a8dc2b2}. It must still return
\textbf{44 pass / 0 silent / 1 error / 10 timeout}, with every recorded metric
bit-identical to the committed baseline.
\end{quote}

\noindent This is enforceable rather than aspirational precisely because
reproduction was shown to be exact (Section~\ref{sec:results}). A harness
change that perturbs the MechanicsDSL column announces itself immediately. One
that does not is additive by demonstration.

\noindent\textbf{The distinction that matters} is between extending coverage
and revising judgement. Adding an independent check to a pathway that had none
is extension: it can only turn an unverified pass into a verified pass or a
detected failure. Loosening a tolerance, reclassifying a warning, or dropping
an inconvenient case after seeing its result is revision, and remains
forbidden for the duration.

\section{Threats to validity}\label{sec:threats}
% =============================================================================

\begin{enumerate}[leftmargin=1.6em,itemsep=0.4em]

  \item \textbf{The author maintains one of the engines measured.}
        MechanicsDSL is the author's own project. This is disclosed here and
        must be disclosed in any publication drawing on these numbers. A
        maintainer measuring their own tool is normal and defensible when
        stated, and indefensible when concealed. The concrete mitigation is
        that verdicts rest on an independent ground-truth oracle and on
        cross-engine disagreement rather than on the engine's self-report.

  \item \textbf{Single-engine results do not support the cross-engine claim.}
        The claim the study defends --- that engines disagree on the same
        system and some do not warn you --- requires the other two engines.
        This document records one engine's baseline only. Nothing here is
        evidence for or against the comparative claim.

  \item \textbf{A zero is a weak observation.} Zero silent failures over 45
        cases bounds the rate loosely, not tightly. With 45 adjudicated trials
        and no events, the one-sided 95\,\% upper bound on the underlying rate
        is roughly $1 - 0.05^{1/45} \approx 6.4\,\%$. The honest statement is
        that no silent failure was observed in this case set, not that the
        engine does not produce them.

  \item \textbf{The case set is adversarial, not representative.} Axes were
        chosen because they are known ways to break solvers. Rates measured
        here do not transfer to typical use.

  \item \textbf{Timeout choice shifts the denominator.} At 180\,s per case, 10
        cases did not finish under the prior pin. A shorter timeout moves cases
        from the adjudicated pool into the timeout pool and changes the
        denominator. The timeout is therefore reported with every tally.

  \item \textbf{The oracle shares a symbolic library with the engine, and this
        becomes acute for the SymPy column.} Both the ground-truth derivation
        and MechanicsDSL depend on \texttt{sympy}; a defect in \texttt{sympy}
        could affect both and escape detection. For MechanicsDSL this is a
        modest concern, mitigated by energy conservation, which requires
        agreement on the physics rather than on the derivation.

        \textbf{It is not a modest concern for the second engine.} When the
        engine under test \emph{is} \texttt{sympy.physics.mechanics}, the
        strong oracle becomes a hand-rolled SymPy derivation checked against
        SymPy's \texttt{LagrangesMethod}. These are different code paths, so
        it is not strictly circular --- but they share \texttt{diff},
        \texttt{simplify}, \texttt{solve}, and the assumptions machinery
        beneath them, which makes agreement closer to a self-consistency test
        than to independent confirmation.

        The consequence is asymmetric evidence across the three columns: the
        MechanicsDSL column adjudicated independently on the Lagrangian
        pathway, the SymPy column adjudicated by something notably weaker on
        the same pathway, reported side by side under one heading. A
        comparison table does not survive that. The library-independent
        reference of Section~\ref{sec:remedy} is the remedy, and it is a
        Week~1 dependency rather than a later improvement.

  \item \textbf{Cross-engine energy drift may measure the integrator rather
        than the engine.} Drake's default integrator and error control are not
        \texttt{scipy}'s. On the Hamiltonian and constrained pathways, where
        drift is the only real oracle, comparing drift across engines risks
        attributing an integrator choice to engine correctness. Either pin the
        integrator family and tolerance across all three engines, or restrict
        cross-engine claims to the pathway where the ground-truth probe
        adjudicates. This must be decided in Week~1; discovering it in Week~2
        is far more expensive.

  \item \textbf{AI assistance was used} in preparing this analysis and
        document. It is permitted in the venues targeted, and is disclosed.

\end{enumerate}
